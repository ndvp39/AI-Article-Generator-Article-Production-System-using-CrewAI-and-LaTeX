## 1. Theoretical Background

### 1.1 Why Programmatic Graphs in Academic Articles
Academic articles rely on visualizations to communicate data trends, comparisons, and results. In an AI-generated pipeline, graphs cannot be manually created — they must be produced programmatically from data and embedded in the LaTeX document. Two complementary approaches exist:

| Approach | Tool | When Used |
|----------|------|-----------|
| **Raster image** | matplotlib → PNG/PDF | Data charts, line plots, bar charts, scatter plots |
| **Vector diagram** | TikZ / PGFPlots | Flowcharts, architecture diagrams, mathematical figures |

This project requires **at least one Python-generated graph** (matplotlib) embedded in the article. TikZ is the secondary option for purely structural diagrams.

### 1.2 matplotlib Architecture
`matplotlib` is Python's primary scientific plotting library. Its architecture:

```
Figure
 └── Axes (subplot)
      ├── Line2D, Bar, Scatter, ...  (artists)
      ├── XAxis / YAxis              (tick marks, labels)
      └── Text, Legend, Title        (annotations)
```

Key design points for academic graphs:
- **DPI:** 150–300 DPI for PNG; vector PDF is infinite resolution.
- **Backend:** Use `Agg` (non-interactive) for headless/server generation — no display required.
- **Figure size:** Set in inches at creation: `fig, ax = plt.subplots(figsize=(6, 4))`.
- **Font:** Match the article font where possible; at minimum use a serif or clear sans-serif.

### 1.3 Embedding Graphs in LaTeX
Generated graphs are embedded via `\includegraphics`:

```latex
\begin{figure}[h]
  \centering
  \includegraphics[width=0.8\textwidth]{figures/graph.pdf}
  \caption{Training loss over epochs for three model configurations.}
  \label{fig:training_loss}
\end{figure}
```

Best practices:
- **PDF format preferred** over PNG for LaTeX inclusion — vector, no pixelation at any zoom.
- **Relative path:** always reference from the `.tex` file directory; `figures/` subdirectory is the convention.
- **`\label{fig:...}`** + `\ref{fig:...}` for cross-referencing; `hyperref` makes figure references clickable.

### 1.4 Non-Interactive Rendering (Agg Backend)
When running headlessly (no display, CI, server):

```python
import matplotlib
matplotlib.use("Agg")   # Must be set BEFORE importing pyplot
import matplotlib.pyplot as plt
```

Failure to set `Agg` before `pyplot` import on a headless system raises:
```
_tkinter.TclError: no display name and no $DISPLAY environment variable
```

### 1.5 PGFPlots and TikZ (Secondary Option)
For diagrams that must match LaTeX typography perfectly (same font, same line weight), `pgfplots` generates plots directly in LaTeX from data:

```latex
\usepackage{pgfplots}
\begin{tikzpicture}
\begin{axis}[xlabel={Epoch}, ylabel={Loss}]
\addplot coordinates {(1,0.9) (2,0.6) (3,0.4) (10,0.1)};
\end{axis}
\end{tikzpicture}
```

Tradeoff: PGFPlots syntax is complex; matplotlib is simpler for the agent to generate correctly. The project uses matplotlib as the primary graph tool and TikZ for structural diagrams only.

### 1.6 Graph Content Requirements for Academic Articles
A graph in an academic article must:
1. Have a **descriptive title** or caption that fully explains what is shown.
2. Have **labeled axes** with units where applicable.
3. Have a **legend** if multiple data series are present.
4. Use **color-blind-friendly colors** or distinct line styles for accessibility.
5. Be **referenced in the text** with `\ref{fig:label}` — orphaned figures (present but never referenced) are poor style.

## 2. Requirements

### 2.1 Functional Requirements

**REQ-GRAPH-01: Minimum One Python Graph**
The article MUST include at least one graph generated by Python code (matplotlib). The graph MUST be relevant to the article's topic — not a placeholder or dummy data.

**REQ-GRAPH-02: Topic-Relevant Data**
The graph data MUST be derived from or directly relevant to the article's subject matter. Acceptable sources:
- Simulated data that illustrates a concept discussed in the article
- Well-known benchmark data (e.g., standard ML datasets' accuracy curves)
- Data explicitly found by the ResearcherAgent

Completely synthetic random data with no relation to the article topic is NOT acceptable.

**REQ-GRAPH-03: Graph Saved as PDF**
The generated graph MUST be saved as a PDF file (`figures/graph.pdf`) alongside the `.tex` file. PNG is acceptable as a fallback but PDF is preferred for resolution independence.

**REQ-GRAPH-04: Graph Referenced in Article**
The graph MUST be embedded in the article with a `\begin{figure}...\end{figure}` environment including:
- `\includegraphics` command with correct relative path
- `\caption{}` with a descriptive caption (≥ 10 words)
- `\label{fig:...}` for cross-referencing
- At least one `\ref{fig:...}` in the article body that references it

**REQ-GRAPH-05: Axes Labeled**
All axes of the graph MUST have text labels. Unlabeled axes are an academic quality failure.

**REQ-GRAPH-06: Legend When Multiple Series**
If the graph contains 2 or more data series, a legend MUST be present.

**REQ-GRAPH-07: Headless Rendering**
Graph generation MUST work without a display. The `Agg` backend MUST be set before any pyplot import.

**REQ-GRAPH-08: GraphGeneratorAgent Code Output**
The `GraphGeneratorAgent` MUST output **executable Python code** as a string. This code, when executed, produces the graph file. The agent MUST NOT attempt to display the graph (no `plt.show()`).

**REQ-GRAPH-09: Graph Code Execution**
`LaTeXCompiler` (or `GraphRunner`) MUST execute the Python code produced by `GraphGeneratorAgent` in an isolated subprocess and verify the output file was created.

**REQ-GRAPH-10: Figures Directory**
All graph files MUST be saved to `results/figures/`. The directory MUST be created if it does not exist.

### 2.2 Non-Functional Requirements

**NFR-GRAPH-01:** Graph generation MUST complete within 30 seconds.  
**NFR-GRAPH-02:** Generated graph file size MUST be < 5 MB (PDF or PNG).  
**NFR-GRAPH-03:** Graph code MUST be valid Python 3.10+ syntax — validated by `ast.parse()` before execution.  
**NFR-GRAPH-04:** Graph execution subprocess MUST have a 30-second timeout; `GraphGenerationError` raised on timeout.  
**NFR-GRAPH-05:** No `plt.show()` calls in generated code — raises `GraphValidationError` on detection.

## 4. Input / Output Contract

### 4.1 `GraphRunner.run(code: str, output_dir: Path) → GraphResult`

| Field | Detail |
|-------|--------|
| **Input** | `code: str` — Python source code from `GraphGeneratorAgent` |
| **Input** | `output_dir: Path` — directory where graph will be saved |
| **Output** | `GraphResult` — result of execution |
| **Raises** | `GraphValidationError` if code fails syntax/security checks |
| **Raises** | `GraphGenerationError` if subprocess exits non-zero or times out |
| **Raises** | `GraphOutputMissingError` if execution succeeds but no graph file found |

### 4.2 `GraphResult` Data Model

```python
@dataclass
class GraphResult:
    success:        bool
    output_path:    Path          # path to generated graph file
    file_format:    str           # "pdf" or "png"
    file_size_bytes: int
    duration_seconds: float
    stdout:         str           # subprocess stdout
    stderr:         str           # subprocess stderr (for debugging)
```

### 4.3 Execution Flow

```python
def run(self, code: str, output_dir: Path) -> GraphResult:
    # 1. Validate syntax
    ast.parse(code)

    # 2. Security checks
    self._check_forbidden_patterns(code)

    # 3. Check for plt.show()
    if "plt.show" in code:
        raise GraphValidationError("plt.show() forbidden in generated code")

    # 4. Create figures directory
    figures_dir = output_dir / "figures"
    figures_dir.mkdir(parents=True, exist_ok=True)

    # 5. Write code to temp file
    script_path = output_dir / "_graph_script.py"
    script_path.write_text(code, encoding="utf-8")

    # 6. Execute in subprocess with cwd=output_dir
    result = subprocess.run(
        [sys.executable, str(script_path)],
        cwd=str(output_dir),
        capture_output=True,
        text=True,
        timeout=30,
    )

    # 7. Verify output file created
    graph_path = figures_dir / "graph.pdf"
    if not graph_path.exists():
        graph_path = figures_dir / "graph.png"
    if not graph_path.exists():
        raise GraphOutputMissingError(result.stderr)

    # 8. Clean up temp script
    script_path.unlink()

    return GraphResult(success=True, output_path=graph_path, ...)
```

## 5. LaTeX Integration

### 5.1 Figure Embedding Template

```latex
\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.85\textwidth]{figures/graph.pdf}
  \caption{%
    <caption text generated by GraphGeneratorAgent — ≥ 10 words describing the graph>
  }
  \label{fig:main_graph}
\end{figure}
```

### 5.2 In-text Reference
The `WriterAgent` MUST include a cross-reference in the article body:
```latex
As shown in Figure~\ref{fig:main_graph}, the training loss decreases
monotonically over epochs, demonstrating convergence of the model.
```

### 5.3 `figures/` Directory in LaTeX Search Path
`\includegraphics` resolves paths relative to the `.tex` file location. Since both `article.tex` and `figures/graph.pdf` are in `results/`, no additional `\graphicspath{}` configuration is needed. If the structure changes, add:
```latex
\graphicspath{{figures/}}
```

## 6. Example: Generated Graph Script

A valid output from `GraphGeneratorAgent` for an AI/ML article:

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import numpy as np

epochs = np.arange(1, 51)
train_loss = 1.0 * np.exp(-0.08 * epochs) + 0.05 * np.random.default_rng(42).random(50)
val_loss   = 1.1 * np.exp(-0.06 * epochs) + 0.08 * np.random.default_rng(7).random(50)

fig, ax = plt.subplots(figsize=(6, 4))
ax.plot(epochs, train_loss, label="Training Loss",   color="#1f77b4", linewidth=2)
ax.plot(epochs, val_loss,   label="Validation Loss", color="#ff7f0e", linewidth=2, linestyle="--")
ax.set_xlabel("Epoch", fontsize=12)
ax.set_ylabel("Cross-Entropy Loss", fontsize=12)
ax.set_title("Model Convergence over Training", fontsize=13)
ax.legend(fontsize=11)
ax.grid(True, alpha=0.3)

import os
os.makedirs("figures", exist_ok=True)
fig.tight_layout()
fig.savefig("figures/graph.pdf", dpi=150, bbox_inches="tight")
plt.close(fig)
```

## 8. Constraints

1. **No plt.show():** Any generated code containing `plt.show()` MUST be rejected and regenerated.
2. **Headless only:** `matplotlib.use("Agg")` MUST appear before any `pyplot` import.
3. **Subprocess isolation:** Graph code runs in a separate subprocess — it cannot import project modules or access the API key.
4. **Topic relevance:** Random noise data with no connection to article content is not acceptable. The agent receives article context and MUST use it.
5. **PDF format preferred:** PNG is fallback only. PDF preserves vector quality in the compiled LaTeX PDF.
6. **No file writes other than graph:** Generated code MUST NOT write any files other than the graph itself.
7. **30-second timeout enforced:** A runaway graph script (e.g., infinite loop) is killed after 30 seconds; `GraphGenerationError` is raised.
8. **Security:** Generated code MUST NOT contain `os.system`, `subprocess`, `eval`, `exec`, `__import__`, or file writes outside `figures/`.

## 9. Alternatives Considered

| Alternative | Why Rejected |
|-------------|-------------|
| **Pre-generated placeholder graph** | Does not satisfy Project.md §3 requirement for a programmatically generated graph relevant to the article topic. |
| **TikZ/PGFPlots for data charts** | PGFPlots syntax is complex; LLM agents reliably produce matplotlib Python but produce error-prone PGFPlots LaTeX. TikZ reserved for structural diagrams only. |
| **Plotly / Bokeh** | Interactive web-based charts; do not export to LaTeX-compatible static PDF without extra tooling. |
| **seaborn** | Built on matplotlib; adds styling but requires separate install. matplotlib is sufficient and is already a dependency. Could be allowed as optional enhancement but not required. |
| **SVG → PDF conversion** | matplotlib can save SVG; SVG requires external `cairosvg` or `inkscape` to convert to PDF for LaTeX. Unnecessary complexity when matplotlib can save PDF directly. |
| **In-process execution (exec())** | Running agent-generated code via `exec()` in the same process is a security risk. Subprocess isolation is the correct approach. |

## 10. Success Criteria

The graph generation system is considered successful when all of the following are true:

- [ ] `GraphGeneratorAgent` produces executable Python code for every article run.
- [ ] Generated code passes all syntax and security checks without manual intervention.
- [ ] Graph file `results/figures/graph.pdf` (or `.png`) is created after pipeline execution.
- [ ] Graph is embedded in `article.tex` with a caption ≥ 10 words and a `\label{}`.
- [ ] Article body contains at least one `\ref{fig:...}` referencing the graph.
- [ ] `\includegraphics` compiles without errors in LuaLaTeX.
- [ ] Graph is visible in the compiled PDF at the correct location in the article.
- [ ] No `plt.show()` detected in any generated graph code.
- [ ] Graph generation completes within 30 seconds.
- [ ] Graph content is visually related to the article topic (manual review).

**Setup:** Graph code with a Python syntax error (e.g., missing colon)  
**Action:** `GraphRunner.run()` called  
**Expected:** `GraphValidationError` raised from `ast.parse()` with line number and error description

### Scenario T-004: Timeout enforcement
**Setup:** Graph code containing `while True: pass` (infinite loop)  
**Action:** `GraphRunner.run()` called  
**Expected:** Subprocess killed after 30 seconds; `GraphGenerationError` raised with "timeout" message

### Scenario T-005: Output file missing after execution
**Setup:** Valid Python code that exits 0 but saves to wrong path (`graph_output.pdf` instead of `figures/graph.pdf`)  
**Action:** `GraphRunner.run()` called  
**Expected:** `GraphOutputMissingError` raised with helpful message about expected output path

### Scenario T-006: Missing axis labels detected
**Setup:** Graph code without `set_xlabel()` or `set_ylabel()`  
**Action:** Static validation check  
**Expected:** `GraphValidationError` raised: "Generated graph code missing axis labels"

### Scenario T-007: LaTeX embedding compiles
**Setup:** `figures/graph.pdf` present; `article.tex` contains `\includegraphics[width=0.8\textwidth]{figures/graph.pdf}`  
**Action:** LuaLaTeX compilation  
**Expected:** No `! LaTeX Error: File 'figures/graph.pdf' not found`; graph visible in PDF

### Scenario T-008: Security check blocks os.system
**Setup:** Graph code containing `import os; os.system("rm -rf /")`  
**Action:** `GraphRunner.run()` called  
**Expected:** `GraphValidationError` raised: "Forbidden pattern 'os.system' in generated code"

**Setup:** Graph code saves to `figures/graph.png` instead of PDF  
**Action:** `GraphRunner.run()` called  
**Expected:** `GraphResult.success=True`; `GraphResult.file_format="png"`; `GraphResult.output_path` points to PNG; no error raised
