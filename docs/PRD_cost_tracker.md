## 1. Theoretical Background

### 1.1 LLM Token-Based Pricing Model
Large Language Model providers charge by **token** — the fundamental unit of text in transformer models. A token is roughly 0.75 words (or ~4 characters) in English; non-Latin scripts (Hebrew, Chinese) may tokenize differently.

Every API call has two token counts:
- **Input tokens:** The prompt sent to the model (system prompt + conversation history + user message).
- **Output tokens:** The completion generated by the model.

Pricing is published per **1 million tokens** (per-MTok), separately for input and output. Output tokens are typically 3–5× more expensive than input tokens because they require sequential autoregressive generation.

**Example (approximate 2025 pricing):**

| Model | Input ($/MTok) | Output ($/MTok) |
|-------|---------------|-----------------|
| Claude Haiku 3.5 | $0.80 | $4.00 |
| Claude Sonnet 3.7 | $3.00 | $15.00 |
| Claude Opus 4 | $15.00 | $75.00 |
| GPT-4o mini | $0.15 | $0.60 |
| GPT-4o | $2.50 | $10.00 |

### 1.2 Why Centralized Cost Tracking?
Without centralized tracking:
- Each agent call consumes tokens invisibly.
- Total cost is unknown until the provider bill arrives.
- No ability to answer "how much would this run cost on a cheaper model?"
- No optimization data — which agent is the most expensive?

The `CostTracker` solves this by aggregating `CallRecord` objects emitted by `ApiGatekeeper` into a structured `CostReport` with per-agent, per-model breakdowns.

### 1.3 Cross-Model Cost Comparison
A key feature of the system is hypothetical cost comparison: given the actual token counts from a real run (on model A), calculate what the same run would have cost on models B, C, D, E. This answers:
- "This run cost $0.45 on Claude Sonnet. It would have cost $0.03 on GPT-4o mini."
- "Switching to Opus would increase cost 5×."

This requires:
1. Storing actual input/output token counts from every call.
2. A pricing table (`model_pricing.json`) with rates for all models.
3. A `compare_model_costs()` method that applies each model's rates to the actual token counts.

### 1.4 Cost Report Structure
The final `CostReport` contains four levels of granularity:

```
CostReport
├── run_summary          (totals across the entire pipeline run)
│   ├── total_calls
│   ├── total_input_tokens
│   ├── total_output_tokens
│   ├── total_cost_usd
│   └── duration_seconds
├── per_agent            (breakdown by agent name)
│   ├── ResearcherAgent: AgentCostEntry
│   ├── WriterAgent:     AgentCostEntry
│   └── ...
├── per_model            (breakdown by model ID)
│   ├── claude-sonnet-3-7: ModelCostEntry
│   └── ...
└── model_comparison     (hypothetical costs on alternative models)
    ├── ModelCostEntry(model="claude-haiku-3-5")
    ├── ModelCostEntry(model="gpt-4o-mini")
    └── ...
```

### 1.5 Pricing Configuration
Pricing data is stored in `config/model_pricing.json` — never hard-coded. This allows updating prices without code changes as LLM providers adjust their rates.

## 2. Requirements

### 2.1 Functional Requirements

**REQ-COST-01: Aggregate All CallRecords**
`CostTracker.build_report()` MUST aggregate all `CallRecord` objects from `ApiGatekeeper.get_call_records()` into a unified `CostReport`. No call MUST be excluded.

**REQ-COST-02: Per-Agent Cost Breakdown**
`CostReport.per_agent` MUST contain one `AgentCostEntry` per distinct `agent_name` seen in `CallRecord` list. Each entry includes call count, total tokens, and total USD cost.

**REQ-COST-03: Per-Model Cost Breakdown**
`CostReport.per_model` MUST contain one `ModelCostEntry` per distinct `model` seen in `CallRecord` list. Each entry includes call count, total tokens, and total USD cost.

**REQ-COST-04: Cross-Model Comparison**
`CostTracker.compare_model_costs()` MUST return a `CostComparison` listing the hypothetical total cost of the same token counts on each model defined in `model_pricing.json`. The actual model used in the run MUST be marked `is_actual=True`.

**REQ-COST-05: USD Cost Calculation**
Cost for each call MUST be calculated as:
```
cost = (input_tokens  / 1_000_000 * price_per_input_mtok)
     + (output_tokens / 1_000_000 * price_per_output_mtok)
```
Pricing values MUST come from `model_pricing.json` only. No hard-coded prices.

**REQ-COST-06: Unknown Model Handling**
If a `CallRecord.model` is not found in `model_pricing.json`, `CostTracker` MUST:
- Set `cost_usd = 0.0` for that call
- Log a warning: `"Unknown model '{model}' — cost set to 0.0"`
- Include the call in token totals despite the unknown cost

**REQ-COST-07: Budget Alert**
`CostTracker` MUST accept an optional `budget_usd: float` parameter. If `CostReport.total_cost_usd > budget_usd`, `CostReport.budget_exceeded = True` and a `BudgetExceededWarning` MUST be emitted.

**REQ-COST-08: Cost Report Serialization**
`CostReport` MUST be serializable to JSON via `CostReport.to_json()` and saved to `results/cost_report.json` at pipeline end.

**REQ-COST-09: Cost Report in ArticleResult**
`ArticleResult.cost_report` MUST contain the `CostReport` for the pipeline run. The SDK method `get_cost_report()` MUST return it.

**REQ-COST-10: Statistics**
`CostReport.run_summary` MUST include:
- `avg_cost_per_call_usd`
- `avg_input_tokens_per_call`
- `avg_output_tokens_per_call`
- `most_expensive_agent` (name + cost)
- `cheapest_model_in_comparison` (model name + hypothetical cost)

### 2.2 Non-Functional Requirements

**NFR-COST-01:** `build_report()` MUST complete in ≤ 100 milliseconds for up to 1000 `CallRecord` entries.  
**NFR-COST-02:** `CostTracker` MUST NOT make any API calls — pure computation over already-collected `CallRecord` data.  
**NFR-COST-03:** Pricing data loaded once at `CostTracker.__init__()` — not re-read on every `build_report()` call.  
**NFR-COST-04:** All monetary values stored as `float` with 6 decimal places precision in JSON output.  
**NFR-COST-05:** `cost_tracker.py` MUST NOT exceed 150 lines. If it does, split into `cost_tracker.py` + `cost_report.py`.

## 5. Input / Output Contract

### 5.1 `CostTracker.__init__(pricing_config_path: Path, budget_usd: float | None = None)`

| Field | Detail |
|-------|--------|
| **Input** | `pricing_config_path` — path to `model_pricing.json` |
| **Input** | `budget_usd` — optional spending cap; triggers `BudgetExceededWarning` if exceeded |
| **Raises** | `ConfigValidationError` if pricing config is malformed |

### 5.2 `CostTracker.build_report(call_records: list[CallRecord]) → CostReport`

| Field | Detail |
|-------|--------|
| **Input** | `call_records: list[CallRecord]` — from `ApiGatekeeper.get_call_records()` |
| **Output** | `CostReport` — complete cost analysis |
| **Raises** | `CostCalculationError` if data is inconsistent (negative tokens, etc.) |
| **Side effects** | Emits `BudgetExceededWarning` if total cost > budget |

**Internal flow:**
```python
def build_report(self, call_records: list[CallRecord]) -> CostReport:
    per_agent = self._aggregate_by_agent(call_records)
    per_model = self._aggregate_by_model(call_records)
    comparison = self._compare_model_costs(call_records)
    summary   = self._build_summary(call_records, per_agent, comparison)
    report    = CostReport(
        run_summary=summary,
        per_agent=per_agent,
        per_model=per_model,
        model_comparison=comparison,
        generated_at=datetime.utcnow().isoformat() + "Z",
    )
    if self.budget_usd and summary.total_cost_usd > self.budget_usd:
        warnings.warn(f"Budget exceeded: ${summary.total_cost_usd:.4f} > ${self.budget_usd:.4f}",
                      BudgetExceededWarning)
    return report
```

### 5.3 `CostTracker.compare_model_costs(call_records: list[CallRecord]) → CostComparison`

| Field | Detail |
|-------|--------|
| **Input** | `call_records` — list with `input_tokens`, `output_tokens` per call |
| **Output** | `CostComparison` — hypothetical cost on every model in pricing config |
| **Logic** | Sums total `input_tokens` and `output_tokens`; applies each model's pricing |

```python
def compare_model_costs(self, call_records: list[CallRecord]) -> CostComparison:
    total_input  = sum(r.input_tokens  for r in call_records)
    total_output = sum(r.output_tokens for r in call_records)

    alternatives = []
    for model_id, pricing in self.pricing_data.items():
        cost = (total_input  / 1_000_000 * pricing["input_price_per_mtok"]
              + total_output / 1_000_000 * pricing["output_price_per_mtok"])
        is_actual = any(r.model == model_id for r in call_records)
        alternatives.append(ModelCostEntry(
            model=model_id, cost_usd=cost, is_actual=is_actual,
            input_tokens=total_input, output_tokens=total_output,
            total_tokens=total_input + total_output,
            call_count=len(call_records),
        ))

    alternatives.sort(key=lambda e: e.cost_usd)
    actual_cost = next(e.cost_usd for e in alternatives if e.is_actual)

    return CostComparison(
        actual_model=...,
        actual_cost_usd=actual_cost,
        alternatives=alternatives,
        cheapest_model=alternatives[0].model,
        cheapest_cost_usd=alternatives[0].cost_usd,
        most_expensive_model=alternatives[-1].model,
        most_expensive_cost_usd=alternatives[-1].cost_usd,
        savings_vs_actual={
            e.model: actual_cost - e.cost_usd
            for e in alternatives if not e.is_actual
        },
    )
```

## 8. Constraints

1. **No API calls:** `CostTracker` is pure computation — it MUST NOT make any network calls.
2. **Config-only pricing:** No price values hard-coded in source. All from `model_pricing.json`.
3. **Unknown models handled gracefully:** Unknown model → cost=0.0 + warning, not an exception.
4. **Immutable input:** `CostTracker.build_report()` MUST NOT modify the `call_records` list.
5. **File size ≤ 150 lines:** `cost_tracker.py` MUST NOT exceed 150 lines; split at `cost_report.py` if needed.
6. **Zero dependencies beyond stdlib + dataclasses:** `CostTracker` imports only `json`, `dataclasses`, `datetime`, `warnings`, `pathlib`. No third-party libraries.
7. **Precision:** Monetary values MUST NOT use floating-point accumulation errors. Use `round(value, 6)` at final report assembly.

## 9. Alternatives Considered

| Alternative | Why Rejected |
|-------------|-------------|
| **Per-agent cost calculation** | Each agent would need pricing config; duplicates logic; no unified report; cross-model comparison impossible without central aggregation. |
| **Hard-coded prices** | Prices change frequently; hard-coded values require code changes for every price update. `model_pricing.json` allows updates without touching source. |
| **Provider SDK cost tracking** | Anthropic SDK and OpenAI SDK each have their own usage tracking, but they only track one provider. We need cross-provider comparison; only our aggregator has all the data. |
| **Cost tracking in ApiGatekeeper** | Gatekeeper is infrastructure (REQ-GK: "no business logic"); cost analysis is a business concern. Separation keeps gatekeeper simple and CostTracker independently testable. |
| **`decimal.Decimal` for money** | Correct for financial software; overkill here where 6 decimal places of `float` precision is sufficient for cost reporting (< $100 pipelines). |
| **Real-time streaming cost** | Streaming token counts mid-call is complex; token counts are only available in the API response object after the call completes. `CallRecord` capture at response time is sufficient. |

## 10. Success Criteria

The cost tracking system is considered successful when all of the following are true:

- [ ] `CostReport` is produced after every pipeline run with zero missing `CallRecord` entries.
- [ ] `cost_report.json` saved to `results/` after every run.
- [ ] Per-agent breakdown is correct: sum of all `AgentCostEntry.cost_usd` equals `RunSummary.total_cost_usd`.
- [ ] Cross-model comparison lists all 5 models from `model_pricing.json`.
- [ ] `cheapest_model` in comparison is correctly identified.
- [ ] `savings_vs_actual` values are accurate: negative values indicate more expensive models.
- [ ] `BudgetExceededWarning` fired correctly when actual cost > configured budget.
- [ ] Unknown model in `CallRecord` logs warning and sets cost to 0.0 without crashing.
- [ ] `build_report()` completes in ≤ 100 ms for a 24-call run.
- [ ] `ArticleResult.cost_report` accessible via `sdk.get_cost_report()` after `generate()`.
